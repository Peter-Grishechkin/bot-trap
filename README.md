# bot_trap: ловушка для самозванцев под видом Googlebot и YandexBot

Создано 2026-11-08. Скрипт читает access-лог вашего сайта, находит запросы с подписью Googlebot или бота Яндекса и проверяет каждый IP по правилам самих поисковиков. Заодно ловит заходы на «приманку»: адрес, закрытый в robots.txt и нигде не упомянутый.

Ничего не блокирует и не ставит на сервер. Только читает логи и печатает отчёт.

Автор — Пётр Гришечкин, SEO-специалист. О SEO, AI и своих инструментах пишу в Telegram-канале [«Разум Петра (SEO, AI и около)»](https://t.me/seo_and_sem).

## Зачем

User-agent бот пишет о себе сам, подделать его легко. Если в логе «Googlebot» оказывается чужим парсером, анализ обхода врёт: считаются чужие запросы. Скрипт показывает, сколько в логе настоящих ботов и сколько самозванцев, и по желанию отдаёт лог без самозванцев.

## Что нужно

- Python 3.8 или новее. Проверка: `python3 --version`.
- Доступ к access-логу сайта (nginx, Apache, формат combined). Логи за несколько дней лучше, чем за час.
- Интернет: для DNS-запросов и скачивания списков IP Google.

Устанавливать ничего не надо. Скрипт — один файл `bot_trap.py`.

## Быстрый старт: проверка лога без приманки

```bash
python3 bot_trap.py scan /var/log/nginx/access.log
```

Лог за прошлые дни обычно лежит рядом в виде `access.log.1`, `access.log.2.gz`. Можно передать несколько файлов сразу, `.gz` читается без распаковки:

```bash
python3 bot_trap.py scan /var/log/nginx/access.log /var/log/nginx/access.log.1 /var/log/nginx/access.log.2.gz
```

Где взять лог на хостинге: ищите в панели раздел «Логи» или «Журналы доступа», скачайте файл и укажите путь к нему.

## Приманка за три шага

1. Придумайте адрес:

   ```bash
   python3 bot_trap.py setup
   ```

   Скрипт выдаст что-то вроде `/seo-trap-29d63c/`. Адрес случайный, у каждого свой.

2. Добавьте его в `robots.txt` в существующую группу `User-agent: *`:

   ```
   Disallow: /seo-trap-29d63c/
   ```

   Больше нигде этот адрес не упоминайте: ни в ссылках, ни в sitemap.xml. Страницу создавать не нужно: запрос к несуществующему адресу тоже попадает в лог.

3. Через несколько дней запустите проверку, указав адрес:

   ```bash
   python3 bot_trap.py scan /var/log/nginx/access.log --trap /seo-trap-29d63c/
   ```

Как это работает: честные Googlebot и YandexBot читают robots.txt и в закрытый раздел не идут. Скрейперы, которые собирают адреса из `Disallow`, иногда идут. Кто зашёл, тот и попал в отчёт. Ловит не всех: бот, который robots.txt вообще не читает, приманку не найдёт. С этим справляется основная проверка по DNS.

## Как проверяется IP

| | Google | Яндекс |
| --- | --- | --- |
| Обратный DNS (IP → имя) | имя из `googlebot.com`, `google.com` или `googleusercontent.com` | имя из `yandex.ru`, `yandex.net` или `yandex.com` |
| Прямой DNS (имя → IP) | должен вернуться тот же IP | должен вернуться тот же IP |
| Списки IP | скачиваются с developers.google.com, совпадение засчитывается сразу | Яндекс списков не публикует, только DNS |

Источники: [Google: Verify requests from Google crawlers](https://developers.google.com/crawling/docs/crawlers-fetchers/verify-google-requests), [Яндекс: Как проверить, что робот принадлежит Яндексу](https://yandex.ru/support/webmaster/ru/robot-workings/check-yandex-robots).

Прямой DNS нужен потому, что обратную запись для IP заполняет его владелец и может вписать туда что угодно. Что `googlebot.com` ведёт обратно на этот IP, подделать нельзя.

## Как читать отчёт

```
== Google: 11 запросов с подписью бота, 4 IP
   настоящие                    4 запросов (36.4%), 1 IP
   САМОЗВАНЦЫ                   6 запросов (54.5%), 2 IP
```

- **настоящие** — IP прошёл проверку.
- **САМОЗВАНЦЫ** — проверка не пройдена, причина указана: нет PTR-записи, PTR не из доменов поисковика, прямой DNS вернул другой IP.
- **не удалось проверить** — DNS не ответил. Это не вердикт, запустите ещё раз позже.
- **локальные IP** — в логе адреса вида 10.x или 192.168.x. Так выглядит прокси или CDN, см. ниже.

В разделе приманки у каждого IP есть пояснение: самозванец, настоящий бот (проверьте robots.txt), либо «не бот поисковика, но robots.txt проигнорировал».

## Сохранить результат

```bash
python3 bot_trap.py scan access.log --trap /seo-trap-29d63c/ \
  --csv fakes.csv --deny-file deny.conf --clean-out access.clean.log
```

- `--csv` — все проверенные IP с причиной и частыми адресами.
- `--clean-out` — копия лога без запросов самозванцев. Её можно отдавать в анализатор логов: обход Googlebot посчитается по настоящим запросам.
- `--deny-file` — список IP для блокировки. По умолчанию `nginx` (`deny 1.2.3.4;`), есть `--deny-format apache` и `plain`. Скрипт ничего не применяет: список просмотрите сами. `--deny-trap-hits` добавляет в него и тех, кто зашёл на приманку.

## Проверить один IP

```bash
python3 bot_trap.py check 66.249.66.1
python3 bot_trap.py check 77.88.5.1 --bot yandex
```

## Частые проблемы

**Все Googlebot оказались «самозванцами» или «локальными».** Сайт стоит за прокси или CDN (Cloudflare и подобные), и в логе записан адрес прокси, а не посетителя. Скрипт напечатает предупреждение. Настройте сервер, чтобы в `$remote_addr` попадал реальный IP. В nginx для этого есть модуль `ngx_http_realip_module` (`set_real_ip_from` и `real_ip_header`), в Apache — `mod_remoteip`. Пока этого нет, вердиктам верить нельзя.

**Не разобрано много строк.** Формат лога не combined. Передайте свой шаблон с группами `ip`, `path`, `ua`, по желанию `time` и `status`. Например, если первым в строке стоит `$http_x_forwarded_for` в кавычках:

```bash
python3 bot_trap.py scan access.log --regex '^\S+ "(?P<ip>[^"]+)" "\S+ (?P<path>\S+) [^"]*" "(?P<ua>[^"]*)"'
```

Если в поле несколько адресов через запятую, берётся первый.

**Настоящий бот не распознан как бот.** Список User-agent зашит в скрипт (`GOOGLE_UA`, `YANDEX_UA` в начале файла), его можно править. Роботы, которых там нет, скрипт просто не проверяет.

**Долго работает на большом логе.** DNS-запрос делается один раз на уникальный IP, результаты на сутки сохраняются в `~/.cache/bot_trap/`. Увеличьте `--workers 32`, если DNS-сервер справляется.

## Что делать с самозванцами

1. Не блокируйте автоматически. Сначала убедитесь, что список не содержит настоящих ботов (см. «локальные IP» и «не удалось проверить»).
2. Заблокировать можно на уровне сервера (`deny` из файла), в файрволе или через CDN/WAF. Блокировка в robots.txt не работает: его соблюдают только честные боты.
3. Маленькому сайту паниковать не нужно: сначала проверьте, что боты вообще создают нагрузку или портят статистику. Это совет Гэри Иллиеса из [интервью](https://www.seroundtable.com/google-gary-illyes-ai-bot-impersonation-42422.html) (Search Engine Roundtable, 30.10.2026).

## Ограничения

- Скрипт проверяет только тех, кто подписался Googlebot или ботом Яндекса. Парсер под видом обычного браузера останется незамеченным (разве что попадётся на приманку).
- У Яндекса нет публичных списков IP, поэтому проверка опирается на DNS. Если DNS-сервер сбоит, IP попадёт в «не удалось проверить».
- Запросы к DNS и к developers.google.com уходят с вашей машины. Содержимое логов никуда не отправляется.
- Протестировано на синтетическом логе и на реальных адресах Google и Яндекса (66.249.66.1, 77.88.5.1). На боевых логах разных хостингов не проверялось.
